State-verified agent safety

The agent said it’s done.
Did the system record it?

SafeAgentEval is a black-box evaluation harness for AI agents that move money, book appointments, and change records. It drives your agent with scripted customer requests, then grades the final state read from your system of record — deterministically. No model decides pass or fail, and an agent’s reply is a claim to be verified, never evidence.

How evaluation works

    

      

        1
        
Seed

        
Your StateProvider seeds a fresh, synthetic world — accounts, bookings, wallets — and can snapshot and reset it. The harness never touches production data.

      

      

        2
        
Say

        
The harness plays the customer through one black-box contract: say(text). Chat, SMS, voice transcripts, and email are all text by the time the agent reads them.

      

      

        3
        
Grade the state

        
The final snapshot is compared to the scenario’s authorized outcomes; reply claims are verified against it. The run is sealed in a hash-linked trace with its provider_trust tier.

      

    

    

      
Deterministic
No LLM judge. The same state always earns the same verdict, so results hold up in CI and in audits.

      
Paired by design
Every adversarial scenario ships with a benign twin where the similar action is correct — an agent that refuses everything fails.

      
Black-box
No access to prompts, weights, or internals. If it takes text and changes state, it can be examined — vendor or in-house.

      
Audit-ready
Hash-linked traces label who operated the StateProvider (harness / auditor / self_reported), so evidence means what it says.

    

  


  
  

    
Scenario packs

    
A domain pack defines one world — its state, its StateProvider, its authorized outcomes. SafeGateBench defines no world: it is a cross-domain overlay of 16 policy, compliance, safety, and PII gates applied inside every pack.

Track A is the fintech track (banking, payments, trading). Track B is the co-design track for new operational domains, built with a design partner in that domain. Every pack tests the same seven failure categories: confirmation gates, state modification, safety under uncertainty, privacy, prompt injection, duplicate transactions, and partial failure.

  


  
  

    
Why grade state instead of output?

    
Output-scoring evaluators answer “did the reply look right?” For agents that change the world, the release question is “did the right thing happen — and only that?”

    

    

      
Output scoringSafeAgentEval

      
        
Object gradedReply text, tool-call trace, judge scoreFinal state of the system of record

        
Who decides pass/failOften an LLM judgeDeterministic comparison to authorized outcomes

        
“You’re booked!” over a pending recordCan score well — it sounds rightContradicted claim + failed state. Fail.

        
Refuses everythingOften looks “safe”Fails the benign twins

        
Evidence producedScores and transcriptsHash-linked trace with a trust tier

      
    

    

    
The two compose well: use output metrics for conversation quality, and SafeAgentEval as the release gate for whether the agent may touch real state.
